# Флорсток · Мобильный кабинет партнёра

Демонстрационная мобильная версия для **https://fm.floorstock.by/**.

Перенесена из существующего кабинета «Флорсток · Кабинет партнёра».
Исходный проект сохранён; мобильная версия развивается отдельно в этом репозитории.

## Возможности

- Обзор продаж и план на месяц.
- Остатки по складам, поиск и фильтры.
- Заказы, статусы, карточка заказа.
- Команда магазина и роли Флорсток / директор / продавец.
- Баллы: один за каждые полные 100 BYN каждого отгруженного заказа. Полный возврат снимает начисление.
- Новости, обучение и сертификаты.
- Демонстрационные изменения сохраняются локально в браузере.

Макет рассчитан на телефон. На большом экране сохраняется узкая мобильная ширина.

## Данные и доступ

Это **демонстрация**, а не подключённая производственная база.
Все исходные записи созданы программно. Записи и приглашения в демо не отправляются на сервер.

Подключение 1С, серверная авторизация, реальные приглашения и общая база не включены:
исходный сервер использовал Cloudflare D1 и вход ChatGPT, которые не запускаются на PHP-хостинге.
Переключение ролей в демонстрации не является механизмом защиты данных.
Не вводите реальные коммерческие или персональные данные в демонстрацию.

## Разработка

Требуется Node.js 22.13+.

```sh
npm ci
npm run dev
npm test
npm run build
```

Исходники находятся в `src/`. Готовая статическая сборка — в `dist/`.
Сборка хранится в репозитории для воспроизводимой публикации без выполнения приложения на FTP-сервере.

## Публикация

В этом репозитории GitHub Actions проверяет бизнес-правила, пересобирает приложение и сверяет готовую `dist/` с исходниками. FTP-секреты здесь не нужны.

Публикацию выполняет единый workflow **Publish FM to hoster.by** в `orkesterro-collab/prioritet-parquet`, где уже настроен пользователь `chatgpt` и секрет `FTP_PASSWORD`.
Он проверяет обновления примерно раз в 10 минут; время запуска расписания зависит от GitHub Actions. Доступен и ручной запуск workflow.

Порядок публикации:

1. Зафиксировать точный SHA ветки `main` этого репозитория.
2. Дождаться успешной проверки сборки именно этого SHA.
3. Скачать только разрешённые готовые файлы из `dist/` и сверить их Git-хеши.
4. Проверить сертификат FTPS и принадлежность FTP-папки домену временным проверочным файлом.
5. Загрузить ресурсы, затем главную страницу; сверить все опубликованные файлы.
6. Записать `version.json` последним, после успешной проверки.

Код приложения не исполняется в задании с FTP-секретом. Секрет между репозиториями не копируется.

Допустимая цель — только `fm.floorstock.by`: существующая папка `/fm.floorstock.by/` при домашней директории FTP `/www` либо `/www/fm.floorstock.by/` при домашней директории `/`.
Посторонние файлы не удаляются. Корень FTP не используется как запасная папка.

Пока SSL поддомена не настроен, для публичной демонстрации явно разрешена проверка по HTTP через `FM_ALLOW_HTTP_BOOTSTRAP=1`. Передача файлов и пароля всегда выполняется через FTPS с проверкой сертификата. Как только HTTPS заработает, проверка автоматически использует его. После настройки SSL этот временный флаг следует убрать из общего workflow.

Не включайте второй независимый издатель в этом репозитории одновременно с общим workflow.
`version.json` содержит контрольный хеш сборки. Демонстрационный кабинет закрыт от поисковой индексации.
